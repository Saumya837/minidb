refactor(parser): extract parseIndex, reject dotted index names

DROP INDEX parsed names inline and accepted dotted/star lexemes, since
the lexer folds '.' and '*' into IDENTIFIER-shaped tokens
(DROP INDEX idx.name failed later at "expected ON" instead of at the name).
Index names now go through parseIndex, which rejects them at the token.

Also fixes DROP errors carrying a doubled prefix
("Syntax error: ..., Syntax error: ..."): an already-formatted message
was being passed as the detail of another parseError.

Decision: DROP INDEX requires ON <table> (MySQL style), not bare
DROP INDEX idx as in Postgres.

Verified:
  DROP INDEX IF EXISTS a, b ON t;
  -> Drop / IF_EXISTS / INDEX_LIST (INDEX: a, INDEX: b) / TABLE: t
  DROP INDEX idx.name ON t;
  -> Syntax error: at or near "idx.name", index name cannot contain '.'
  DROP INDEX emp.* ON t;
  -> Syntax error: at or near "emp.*", index name cannot contain '.'
  DROP INDEX idx;
  -> Syntax error: at or near ";", expected ON
  DROP INDEX ;
  -> Syntax error: at or near ";", expected an identifier
